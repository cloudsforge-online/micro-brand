The estate's actual artwork: 98 files — 94 across 14 surfaces, plus the four that belong to the
two currency identities rather than to a surface — every one of them generated by **FLUX 2
Pro** on Azure AI Foundry and recorded in [MANIFEST.json](MANIFEST.json) with the model, the exact
prompt, the checksum, the delivered size and the number of times it had to be regenerated.

**All of this artwork is AI-generated.** That is stated here, on every manifest entry, and in the
licence string carried by each asset. The estate already discloses it and must continue to.

**A second generated set is on disk and is not shipped.** `candidates/gpt-image-2/` holds the same
brief drawn by a different model, with its own manifest, and `providers.json`'s `reference` field is
the single thing that decides which of the two `assets/` holds. **§8 is the runbook**: how to look
at both without switching, how to switch, and how to switch back. The badge above names what ships
today and nothing else. [COMPARISON.md](COMPARISON.md) §11 is the evaluation, including the kinds
where the challenger is plainly worse.

Design authority: [`ecosystem/24-asset-model-comparison.md`](https://github.com/cloudsforge-online/micro-docs/blob/main/ecosystem/24-asset-model-comparison.md)

### Three partial sets, and why each is finished rather than unfinished

Every one of these has been mistaken for a gap at least once. They are decisions, and undoing one
costs money to produce an asset with nowhere to go.

- **`admin`, `lantern`, `beacon` — no OG card, no social banner.** Those two kinds exist to be
  scraped by a social platform or shown on a repository page, and a surface only an operator can
  open is linked from neither. `micro-admin-web/test/brand-chrome.test.ts` asserts the absence in
  its own repository, so adding a card there turns a correct test red.
- **`status`, `explorer` — no mark, no wordmark.** Both carry `markId: null` in the registry
  *deliberately*: a status page is Beacon with its internals removed and an explorer is part of
  Forge Network, and neither claims a mark of its own. What each does need is what a **separate
  host** cannot inherit — a favicon, or the tab shows the browser's blank page icon, and an `og`,
  or a shared link renders as a bare URL. That is the whole of `PUBLIC_CHILD` in `plan.ts`.
- **`developers` — no social banner.** It gained an `og` because devportal-web is public and its
  links get shared; a repository social preview is a separate question nobody has asked.

### Surfaces with no set at all, on purpose

- **`faucet`.** It has a registry row, but that row reads `subdomain: 'network'`,
  `basePath: '/faucet'` — it is **a route on the Network site, not a host**, so it renders under
  `network`'s favicon and `network`'s OG card and can hold no chrome of its own. `micro-faucet` is
  a backend API with no `index.html` and no `public/`. A `assets/faucet/` directory would be five
  files nothing can reference.
- **`wallet`.** The same shape: `subdomain: 'hub'`, `basePath: '/wallet'`.
- **`nda`.** *Ninety Days After* is a Forge Worlds title whose port, `micro-nda`, is a backend
  service on port 4110. It has no frontend in this estate, no registry row and therefore no
  accent — see §7.
- **The service hostnames** (`nimbus`, `account`, `api`, `pay`, `keyvault`, `emberkin`). No browser
  chrome; `emberkin`'s art is its own repository, `micro-emberkin-assets`. These hosts serve no HTML
  by design — `servesUi: false` — so they are never presented as pages to open. `worlds-api` was on
  this list and is **gone**: it was folded into `api.<apex>`, it never had a public DNS record, and
  its registry row was deleted on 2026-08-05. It needs no accent because it is not a surface.

### `social/` — eleven files that are not assets

[`social/`](social/README.md) holds the org's profile artwork: avatars, platform banners and two
explorer screenshots. It is **not** part of the 98 and not in `MANIFEST.json`, because nothing in it
was generated — the avatars are resamples of assets that *are* in the manifest, the banners compose
the product's own header lockup, and a screenshot is a photograph of a running system. `verify.py`
walks `assets/**/*.png`, so the directory is outside its reach by construction; its own README
carries the provenance instead.

**`assets/site/wordmark-1024x384.png` is the first real CloudsForge wordmark the estate has had.**
The file previously called `wordmark.png` elsewhere in the estate is the *Ninety Days After*
lockup, which is a different product's artwork under the company's name.

## 2. How it was generated

`generate.ts` drives **`@cloudsforge/studio`'s own engine**. It imports `backend.ts`, `prompt.ts`,
`specs.ts` and `sizing.ts` from the sibling service verbatim and reads the work list out of the
surface registry at `ui/packages/ui/src/surfaces.ts`; `studio/` itself was not modified. Every
verified fact about this endpoint already lives in those modules under test, and a second copy of
it here would be a second place for it to rot.

It does **not** drive the service's HTTP route. That path additionally needs Postgres with
migrations applied, a JWT issuer, a per-account credit ledger with a spend cap and the leased-job
worker — all of which exists so a *multi-tenant* service can bill an account and survive a rolling
deploy mid-generation, and none of which has a job to do in a one-off run of the estate's own
artwork. The trade the brief allows is that the same provenance is written anyway, so
`MANIFEST.json` carries every column `generation_jobs` and `assets` would have carried, including
the attempts that failed.

```bash
cd ../studio && node --import tsx ../brand/generate.ts              # everything missing
cd ../studio && node --import tsx ../brand/generate.ts --force --only site:wordmark
cd ../studio && node --import tsx ../brand/generate.ts --provider gpt-image-2   # a candidate set
python3 verify.py                                                   # measure what is measurable
python3 verify.py --provider gpt-image-2                            # one set, its own manifest
python3 sheet.py                                                    # contact sheets into review/
```

It runs from `studio/` so `tsx` resolves out of that workspace. Credentials are read from
`../studio/.env.local`, held in one variable and never written, logged or echoed. **This
repository contains no credential and never should**; `.gitignore` covers `.env*` and the working
tree was scanned for the key fragment before the first commit.

Each provider names **the variables it reads** in its `providers.json` entry's `env` block, and
names them only — never a value, and never a value's prefix. `flux-2-pro` reads
`AZURE_FOUNDRY_ENDPOINT` and `AZURE_FOUNDRY_API_KEY`; `gpt-image-2` reads `AZURE_IMAGES_ENDPOINT`
and `AZURE_IMAGES_KEY`, which `studio/.env.local` sources from
`~/.config/cloudsforge/azure-images.env` (mode 600, outside every repository).

**Nothing on a failure path prints a caught error verbatim, and that is a rule with an incident
behind it.** Node's `fetch` puts the whole request URL — key included, when the key is a query
parameter — into the exception message, and a credential leaked out of this estate exactly that way
once. Every adapter in `backends.ts` reports through `redact()`, which truncates and strips, and the
response body is read **in full** for parsing while only the redacted form reaches an attempt's
`detail`. Those two are deliberately different lengths: capping the *parsed* string is how a run
once generated and paid for ten images and delivered none, because a 205,000-character success
envelope was truncated to 4,000 and handed to `JSON.parse`. `parity.test.ts` now asserts a
real-sized envelope decodes whole.

### The prompt

The style paragraph, the composition line per kind and the prohibitions all come from
`studio/src/prompt.ts`, which derives them from design-system.md §7. `plan.ts` supplies the one
idea each mark is built around, written as prose from the six hand-authored SVGs in
`docs/ecosystem/assets/mark-*.svg`, so the generated marks are recognisably the same concept.

`generate.ts` appends three clauses of its own, each added *after* a defect was seen in this run's
own output and each named in the source with the failure it answers:

- **the ground clause**, after the first live image came back on a mid-grey taupe field with
  construction guides ruled across it;
- **the accent clause**, after Hub's OG card drew its ridge in grey with a five-pixel ember
  diamond and Worlds drew its whole settlement in white;
- **the lettering clause**, after Market's banner came back reading "Sftware Company" — the style
  paragraph's own opening words, misspelt and rendered as art — and Trade's card came back
  captioned "Quench Curve" with the baseline labelled "ash ridge", which is this repository's
  vocabulary drawn as a diagram annotation.

Every asset's manifest entry stores the prompt **as it was actually sent**, so an entry generated
before a clause existed does not claim to have had it.

## 3. The four FLUX traps

All four were verified by real requests against the live resource, and all four contradict what
the URL or the documentation implies. They are encoded in `studio/src/backend.ts` and
`studio/src/specs.ts`; they are repeated here because anyone reading this repository is one step
away from calling the endpoint by hand.

1. **`model` is required in the body**, even though the path already names the model. Omitting it
   is `400 no_model_name`.
2. **The body spelling and the path spelling differ.** The path segment is `flux-2-pro`; the model
   name is `FLUX.2-pro`, with dots. Sending the path spelling is `404 DeploymentNotFound`, which
   looks exactly like a model that was never deployed.
3. **`aspect_ratio` and `size` are accepted and silently ignored.** Only `width`/`height` are
   honoured. A parameter that is accepted and ignored is worse than one that is rejected, because
   nothing fails.
4. **`width`/`height` are floored to a multiple of 16.** `1200x630` comes back `1200x624`. So any
   size not on the grid is asked for rounded **up** and cut down — never upscaled, because a
   centre crop invents no pixel and an upscale turns a crisp vector edge into a soft one. That is
   the whole reason the OG card ships as a 630 cut from a generated 640, with the as-delivered
   640 kept beside it.

And a fifth, less a trap than a requirement: **`output_format:"png"` or you get JPEG**, and a JPEG
brand mark has no transparency and visible ringing on flat vector edges.

## 4. Provenance, C2PA and the watermark

**Every image FLUX returns carries C2PA provenance and a Microsoft invisible watermark**, roughly
100KB of it, and every file here was delivered with one.

**2 of the 98 files in this repository still carry the C2PA box, and they are the two currency
marks.** Every other file lost it, and that is the truth rather than a regression. Two re-encodes
stand between delivery and what is committed, and neither can keep the box:

- the **42 derivatives** — the OG crops, the avatar and the 192/32 favicons — go through Pillow,
  which has never heard of a `caBX` chunk;
- the as-delivered files go through `normalise_ground.py`, which snaps the ground to exactly
  `#12100f` (§5) and rebuilds the PNG from IHDR/IDAT/IEND, keeping no ancillary chunk.

`currency-ember/mark` and `currency-spark/mark` were generated after the ground snap was last run
over the set and have never been through it, so theirs survived. **This paragraph read "no file"
and "all 93" until those two were counted** — a categorical claim about provenance that the bytes
contradicted, in the section whose whole subject is not asserting provenance you no longer carry.
`python3 claims.py` now measures both figures off the bytes on every run, the same way `verify.py`
measures the per-asset flag, so the sentence cannot outlive the fact a second time.

The second one *must* drop it. A C2PA manifest is a signed assertion bound to the pixels, and that
script exists to change the pixels; a box surviving a ground snap would be a box asserting
something no longer true. What is kept either way is the invisible pixel watermark, which is in the
image data rather than in a chunk — that is the vendor's claim, and this repository has no detector
with which to confirm it, so it is recorded as their claim and not as a measurement.

**This was wrong in the manifest until it was measured.** 54 entries carried `c2pa: true` with no
box in the file. `normalise_ground.py` re-recorded `sha256` and `byteSize` after rewriting the
pixels but not the disclosure, and `verify.py` checked dimensions, checksum, ground and accent and
never the disclosure — so the verifier stayed green while the repository asserted provenance it had
lost. Both holes are closed: `refresh_manifest` now re-records `c2pa` alongside the checksum, and
`verify.py` fails any entry whose flag disagrees with its bytes. The check is about **truth, not
presence** — an asset is free to carry no C2PA box, and it may not say otherwise.

Every derivative names its source in `derivedFrom` and the as-delivered OG card is kept beside its
crop, because a file claiming provenance it no longer carries would be worse than one that admits
it. That sentence was already here. It is now enforced.

Resizing is Pillow, not macOS `sips`. design-system.md §7 item 3 names `sips` as the reason the
estate's resize stage exists on exactly one laptop, and "twelve game masters currently sit at
1024 against declared 512/256 because the refit has never been run".

### Licence position

Each entry records:

> `cloudsforge-generated: commercial use permitted; AI-generated, C2PA provenance retained`

FLUX output through Azure AI Foundry is licensed to the customer for commercial use. The string is
a constant imported from `studio/src/assets.ts` rather than free text, because an asset whose
licence is whatever somebody typed is an asset nobody can clear for use. The **artwork** is
AI-generated and disclosed as such; the code in this repository is MIT, as the rest of the estate
is.

## 5. What the run cost, and what needed doing twice

54 generated images shipped plus 39 derivatives, from **80 generations** — 26 of them retries. At
the provider's flat 3 units an image that is 240 units of spend for 162 units of kept artwork.
(The first pass of eleven surfaces was 44 shipped from 65 generations; `foresight`, `status`,
`explorer` and the `developers` OG card followed.)

Every asset was inspected by eye on a contact sheet as well as measured by `verify.py`, which
checks dimensions, checksum, C2PA disclosure, ground darkness and accent coverage on all 98 files.
It reports zero failures.

**What FLUX 2 Pro handled well:**

- **Wordless marks.** Twelve marks, **one retry between them**, and every one recognisably the same
  idea as the hand-authored SVG it was derived from. The anvil-and-spark, the hearth flame, the
  stall awning and the quench curve all came back essentially as specified.
- **Wordmark lettering, unexpectedly.** All nine wordmarks spelled their name correctly, with
  correct capitalisation of the medial `F` in "CloudsForge", **on the first attempt in seven of
  nine** — only `hub` and `trade` needed a second. Text rendering is what image models are worst
  at, and this is the one kind that did not need the retries.

The retries are not spread evenly, and where they land is the finding. Per kind, across the whole
run: `mark` 12 files / 1 retry, `wordmark` 9 / 2, `favicon` 14 / 5, `social` 8 / 4, and **`og` 11
files / 14 retries** — more regenerations than assets. The wide lettered card is over half the
run's wasted spend on its own.
- **Flat vector discipline.** No gradients, no bevels, no photographic texture, once the ground
  was pinned. Consistent stroke weight within an image.

**What it handled badly, and what is worth hand-authoring instead:**

- **Text on a *wide* composition.** The failures were all on OG cards and social banners, never on
  wordmarks: "Sftware Company", "Cartre Pere", "Quench Curve / ash ridge", and one card with the
  name simply absent. Given a wide field and a lot of empty space the model fills it with invented
  text, and the source of the invention is the *prompt's own vocabulary*. **Set the type on OG and
  social cards by hand** — composite the generated mark onto a card and typeset the name. It is
  ten lines of Pillow and it removes the entire failure class.
- **Favicons.** Five of fourteen came back as the mark *plus* a smaller framed copy of itself, like
  a preview thumbnail pasted into the artwork. "Draw it simpler than the full mark" is read as
  "show both". A favicon is a downscale of the mark and should simply be one.
- **Exact accent fidelity.** Every accent renders lighter than the hex it is given, and lightening
  drags the hue — measured drift runs 1 to 22 degrees across the set, and `trade` needed seven
  attempts before its card was both dark-grounded and the right green. **Recolour rather than
  reprompt**: generate in greyscale and map the ink to the registry hex.
- **Sticking to a dark ground.** The very first image came back mid-grey taupe with construction
  guides drawn in, and one later attempt inverted to a near-white field. The ground had to be
  restated as its own final paragraph, and it still needs verifying per asset.
- **Anything requiring an exact count.** "Five valance strokes", "four segments", "a nine-cell
  grid" are approximated, always plausibly and never exactly.

The short version: **let the model draw the marks, and set the type yourself.**

## 6. Reproducing

`generate.ts` imports from the sibling `studio/` and `ui/` checkouts, so this repository is not
self-contained — the artefacts are, the runner is not. That is the same arrangement the estate's
other packages use. Clone `cloudsforge-online/micro` beside it, put a Foundry endpoint and key in
`studio/.env.local`, and run.

There is **no seed** on any entry, and the column says `null` rather than being absent. This
deployment of FLUX 2 Pro accepts no seed parameter, so nothing true could be recorded; the field
is kept so the absence is a stated fact and a seeded model later has somewhere to put one. **These
images are therefore not bit-reproducible.** The prompt, model and checksum are recorded so a
regeneration can be *compared* to what shipped, which is what provenance is for.

## 7. *Ninety Days After*, and why it has no set here

`micro-nda` has no artwork and `micro-emberkin-assets` has 134 files, which reads like an
oversight. It is not one, and the reason is worth writing down because the comparison will be made
again.

**Emberkin has art because Emberkin has a surface and a specification.** `micro-emberkin-web` is a
frontend on its own subdomain, `emberkin` is a registry row with an accent, and the run had
`kindred-upstream/docs/ART_BIBLE.md` plus `content/{species,visuals,types,campaign}.json` to read
fifty per-Kin briefs out of. **NDA has none of the four.** `micro-nda` is a backend service on port
4110; there is no `micro-nda-web`, no `nda` key in `SurfaceKey`, no compose entry, no hostname —
and therefore **no registry accent to draw it in**, which alone stops a run: `generate.ts` refuses
to start when `plan.ts` names a surface the registry does not (`assertPlanMatchesRegistry`).

**And it is not artless.** The frozen ancestor ships a finished set at
`stack/repos/ninety-days-after/apps/game/art/` — 18 masters at 1024², six resource icons, six
terrain tiles, a homestead avatar, a logo and the 1536x1024 wordmark, with `art/build.mjs`
resampling them into `public/assets` as PNG and WebP. It is what has never been ported, not what
has never been made. Three files in that directory — `cloudsforge-logo.png`, `mark-forgepay.png`,
`mark-games.png` — are ancestor *estate* chrome and are superseded by `assets/site/` here; the
other 15 are the game's own.

That wordmark is the file §1 refers to. It is a rusted steel sign, screwed at the corners, reading
NINETY DAYS AFTER beside a sunburst, baked onto **opaque white** — photographic weathered realism,
which is the opposite direction to this repository's flat vector on `#12100f`. It was never a
CloudsForge lockup and the estate should stop treating it as one.

**What an NDA run would cost, when there is something to run it for.** Not this repository's job —
a game art set belongs in `micro-nda-assets` beside `micro-emberkin-assets`, for the reason that
repository states: `prompt.ts`'s direction is "flat geometric vector, one accent, no gradients",
correct for a software brand mark and wrong for a terrain tile. Fifteen game images plus a title
set of seven — mark, wordmark, capsule, hero, OG, its as-delivered source, social — is **22
generated**, and at Emberkin's observed 1.35 generations per kept image about **30 calls, 90 units**.
The prerequisites are the expensive part and none of them is art: an `nda` registry row with an
accent that clears the six product accents, a written art direction to replace the ancestor's
absent one, and a frontend for any of it to appear on.

**Decision: nothing generated.** Spending on assets for a surface that does not exist, in an accent
nobody has chosen, to an art direction nobody has written, would produce files that cannot be
wired, cannot be verified against a registry and would be regenerated the day the real surface
lands.

## 8. Two sets on disk: how to look at both, how to switch, how to switch back

There is more than one generated set here now. `assets/` holds the **shipped** one and
`candidates/<id>/` holds every set on trial; which is which is one field, `reference`, in
[providers.json](providers.json). This section is the runbook for the three things anybody ever
wants to do with that arrangement.

The switch is **one command and its own inverse**, and the reason it is a script rather than four
lines of `mv` in this README is that a half-finished swap is the one state that loses artwork: the
shipped tree is out of `assets/` and the candidate has not arrived, and now nothing in the estate
has a favicon and the thing you would reach for to put it back is the directory you just moved.
`promote.py` does the moves in an order that cannot leave that gap unattended, re-derives every
checksum in **both** manifests afterwards, and rolls back file by file if any step fails.

### Look at both, without switching anything

```bash
python3 sheet.py --provider gpt-image-2         # contact sheets into review/
python3 compare.py --common                     # side-by-sides into review/compare/, and the numbers
python3 materialise.py --provider gpt-image-2 --into /tmp/gpt-image-2
```

`compare.py --common` is the one to reach for while a candidate is still generating: it measures
only the assets **every** selected set holds, so a partial candidate is compared against the same
partial slice of the reference rather than being scored against assets it has not been asked for
yet. Without it, an incomplete set reads as a worse set.

`materialise.py` resolves a set **by identity** — surface, kind, declared size — and writes it into
a directory laid out exactly like `assets/`, so a candidate can be pointed at a running web app, or
dropped into a design tool, or diffed against the shipped tree, without `reference` moving and
without anything in the repository changing. It refuses to write a partial tree (`IncompleteSetError`)
rather than producing a directory that silently lacks a favicon, and it names anything it cannot
ship — an as-delivered native at a size no surface declares — with the `-asdelivered` suffix so a
file that must not be deployed cannot be deployed by accident.

### Switch

```bash
python3 promote.py --provider gpt-image-2 --dry-run   # says exactly what would move, moves nothing
python3 promote.py --provider gpt-image-2
```

What it does, in this order, and why the order is the whole design:

1. **Refuses to start** unless the winner's set is complete by `materialise.resolve`, its
   `python3 verify.py --provider <id> --as-shipped` subprocess is green, and no destination path is
   still occupied by the time the plan needs it. All three checks happen before a single byte moves.

   **`--as-shipped` is not decoration and the flag exists because the first real promotion needed
   it.** `verify.py` holds brand conformance — ground luma, accent floor, third hue — fatal for the
   **shipped** set and reported-but-not-fatal for a candidate, because a candidate is on trial and
   "this model drew it too pale" is evidence rather than a broken build. The consequence is that a
   candidate can exit 0, be promoted on the strength of that, and turn the repository red the
   moment it lands. `gpt-image-2` does this today: `hub/social` carries 0.32% accent against a 1%
   floor, which was a `warn` line for the whole evaluation and is a `FAIL` the second it is
   shipped. So the gate asks the only question a promotion cares about — *what would this set score
   if it were the shipped one* — and **as of today it refuses to promote `gpt-image-2` for that one
   asset.** That refusal is the machinery agreeing with COMPARISON.md §11.5 rather than a second
   opinion: fix the asset, or accept the deviation knowingly with `--skip-verify`, which still runs
   the completeness and checksum checks.
2. **The loser vacates first.** `assets/`, `MANIFEST.json`, `native/` and `DEPLOYMENT.json` move
   from the repository root into the outgoing provider's `candidates/<old-id>/`. The previous
   reference is **demoted, never deleted** — it becomes a candidate beside the others, its manifest
   and its as-delivered natives intact, and promoting it back is the same command with the two ids
   the other way round.
3. **The winner moves in**, from `candidates/<new-id>/` to the root.
4. **Both manifests are re-derived off the bytes** before the registry is touched — every `sha256`
   in the incoming manifest and every `sha256` in the outgoing one. A move that corrupted a file
   fails here, with both trees still on disk.
5. **Only then is `providers.json` edited**, and surgically: the `reference` field, and the
   `root`/`shipped` pair on each of the two entries. Exactly five lines change. It is a text edit
   rather than a load-and-dump because this file does **not** round-trip through `json.dumps` in
   either `ensure_ascii` mode — it mixes escaped and literal em dashes — and a promotion that
   silently reformatted 350 lines of registry commentary would bury its own five-line change.

Any failure at any step rolls the moves back one file at a time and leaves the registry alone.

### Switch back

```bash
python3 promote.py --provider flux-2-pro
```

That is the whole of it. The inverse is not a special mode, a `--revert` flag or a backup: it is the
same command naming the other provider, because step 2 demoted rather than deleted. The registry
rewrite is checked to be exactly invertible — running the rewrite in the opposite direction over
the promoted file reproduces the original bytes — so a switch and a switch back leave this
repository where it started.

### What a switch does NOT do

- **It does not touch the sibling repositories.** Around twenty of them hardcode
  `assets/<surface>/favicon-32x32.png`; that path is stable across a promotion **by design**, which
  is why the reference set's root is the repository itself rather than `sets/flux/`. A promotion
  changes the bytes at those paths and no consumer's path.
- **It does not re-derive derivatives.** A promoted set ships the derivatives its own manifest
  records, generated by `derive.py` from that set's own natives. Nothing is inherited across a
  switch.
- **It does not normalise the ground.** `normalise_ground.py` hardcodes `Path("assets")` and takes
  no `--provider`, so running it after a promotion would rewrite the newly shipped set's pixels and
  strip its C2PA boxes. **It is not part of the promotion and must not be added to it** without
  first giving it the `--provider` argument it does not have; see COMPARISON.md §11.2, where that
  same hardcoded path is the confound in the ground comparison.
