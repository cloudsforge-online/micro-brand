# CloudsForge brand assets

The estate's actual artwork: 73 files across 11 surfaces, every one of them generated by **FLUX 2
Pro** on Azure AI Foundry and recorded in [MANIFEST.json](MANIFEST.json) with the model, the exact
prompt, the checksum, the delivered size and the number of times it had to be regenerated.

**All of this artwork is AI-generated.** That is stated here, on every manifest entry, and in the
licence string carried by each asset. The estate already discloses it and must continue to.

## 2. How it was generated

`generate.ts` drives **`@cloudsforge/studio`'s own engine**. It imports `backend.ts`, `prompt.ts`,
`specs.ts` and `sizing.ts` from the sibling service verbatim and reads the work list out of the
surface registry at `ui/packages/ui/src/surfaces.ts`; `studio/` itself was not modified. Every
verified fact about this endpoint already lives in those modules under test, and a second copy of
it here would be a second place for it to rot.

It does **not** drive the service's HTTP route. That path additionally needs Postgres with
migrations applied, a JWT issuer, a per-account credit ledger with a spend cap and the leased-job
worker — all of which exists so a *multi-tenant* service can bill an account and survive a rolling
deploy mid-generation, and none of which has a job to do in a one-off run of the estate's own
artwork. The trade the brief allows is that the same provenance is written anyway, so
`MANIFEST.json` carries every column `generation_jobs` and `assets` would have carried, including
the attempts that failed.

```bash
cd ../studio && node --import tsx ../brand/generate.ts              # everything missing
cd ../studio && node --import tsx ../brand/generate.ts --force --only site:wordmark
python3 verify.py                                                   # measure what is measurable
python3 sheet.py                                                    # contact sheets into review/
```

It runs from `studio/` so `tsx` resolves out of that workspace. Credentials are read from
`../studio/.env.local`, held in one variable and never written, logged or echoed. **This
repository contains no credential and never should**; `.gitignore` covers `.env*` and the working
tree was scanned for the key fragment before the first commit.

### The prompt

The style paragraph, the composition line per kind and the prohibitions all come from
`studio/src/prompt.ts`, which derives them from design-system.md §7. `plan.ts` supplies the one
idea each mark is built around, written as prose from the six hand-authored SVGs in
`docs/ecosystem/assets/mark-*.svg`, so the generated marks are recognisably the same concept.

`generate.ts` appends three clauses of its own, each added *after* a defect was seen in this run's
own output and each named in the source with the failure it answers:

- **the ground clause**, after the first live image came back on a mid-grey taupe field with
  construction guides ruled across it;
- **the accent clause**, after Hub's OG card drew its ridge in grey with a five-pixel ember
  diamond and Worlds drew its whole settlement in white;
- **the lettering clause**, after Market's banner came back reading "Sftware Company" — the style
  paragraph's own opening words, misspelt and rendered as art — and Trade's card came back
  captioned "Quench Curve" with the baseline labelled "ash ridge", which is this repository's
  vocabulary drawn as a diagram annotation.

Every asset's manifest entry stores the prompt **as it was actually sent**, so an entry generated
before a clause existed does not claim to have had it.

## 3. The four FLUX traps

All four were verified by real requests against the live resource, and all four contradict what
the URL or the documentation implies. They are encoded in `studio/src/backend.ts` and
`studio/src/specs.ts`; they are repeated here because anyone reading this repository is one step
away from calling the endpoint by hand.

1. **`model` is required in the body**, even though the path already names the model. Omitting it
   is `400 no_model_name`.
2. **The body spelling and the path spelling differ.** The path segment is `flux-2-pro`; the model
   name is `FLUX.2-pro`, with dots. Sending the path spelling is `404 DeploymentNotFound`, which
   looks exactly like a model that was never deployed.
3. **`aspect_ratio` and `size` are accepted and silently ignored.** Only `width`/`height` are
   honoured. A parameter that is accepted and ignored is worse than one that is rejected, because
   nothing fails.
4. **`width`/`height` are floored to a multiple of 16.** `1200x630` comes back `1200x624`. So any
   size not on the grid is asked for rounded **up** and cut down — never upscaled, because a
   centre crop invents no pixel and an upscale turns a crisp vector edge into a soft one. That is
   the whole reason the OG card ships as a 630 cut from a generated 640, with the as-delivered
   640 kept beside it.

And a fifth, less a trap than a requirement: **`output_format:"png"` or you get JPEG**, and a JPEG
brand mark has no transparency and visible ringing on flat vector edges.

## 4. Provenance, C2PA and the watermark

**Every image FLUX returns carries C2PA provenance and a Microsoft invisible watermark**, roughly
100KB of it. All 44 generated files carry it, verified by reading the `c2pa` marker out of the
bytes rather than assuming it from the vendor.

The 29 derivatives — the OG crops and the 192/32 favicons — are re-encoded by Pillow, which has
never heard of a `caBX` chunk, so **they lose the C2PA box while keeping the invisible pixel
watermark**. That is why every derivative names its source in `derivedFrom`, why the as-delivered
OG card is kept beside its crop, and why `c2pa` on a derivative reads `false`: it is measured on
the bytes written, not inherited. A file claiming provenance it no longer carries would be worse
than one that admits it.

Resizing is Pillow, not macOS `sips`. design-system.md §7 item 3 names `sips` as the reason the
estate's resize stage exists on exactly one laptop, and "twelve game masters currently sit at
1024 against declared 512/256 because the refit has never been run".

### Licence position

Each entry records:

> `cloudsforge-generated: commercial use permitted; AI-generated, C2PA provenance retained`

FLUX output through Azure AI Foundry is licensed to the customer for commercial use. The string is
a constant imported from `studio/src/assets.ts` rather than free text, because an asset whose
licence is whatever somebody typed is an asset nobody can clear for use. The **artwork** is
AI-generated and disclosed as such; the code in this repository is MIT, as the rest of the estate
is.

## 5. What the run cost, and what needed doing twice

44 images shipped, from **65 generations** — 21 of them retries across 13 assets. At the
provider's flat 3 units an image that is 195 units of spend for 132 units of kept artwork.

Every asset was inspected by eye on a contact sheet as well as measured by `verify.py`, which
checks dimensions, checksum, ground darkness and accent coverage on all 73 files. It reports zero
failures.

**What FLUX 2 Pro handled well:**

- **Wordless marks.** Eleven marks, one retry between them, and every one recognisably the same
  idea as the hand-authored SVG it was derived from. The anvil-and-spark, the hearth flame, the
  stall awning and the quench curve all came back essentially as specified.
- **Wordmark lettering, unexpectedly.** All eight wordmarks spelled their name correctly, with
  correct capitalisation of the medial `F` in "CloudsForge", on the first attempt in seven cases.
  Text rendering is what image models are worst at, and this is the one kind that did not need the
  retries.
- **Flat vector discipline.** No gradients, no bevels, no photographic texture, once the ground
  was pinned. Consistent stroke weight within an image.

**What it handled badly, and what is worth hand-authoring instead:**

- **Text on a *wide* composition.** The failures were all on OG cards and social banners, never on
  wordmarks: "Sftware Company", "Cartre Pere", "Quench Curve / ash ridge", and one card with the
  name simply absent. Given a wide field and a lot of empty space the model fills it with invented
  text, and the source of the invention is the *prompt's own vocabulary*. **Set the type on OG and
  social cards by hand** — composite the generated mark onto a card and typeset the name. It is
  ten lines of Pillow and it removes the entire failure class.
- **Favicons.** Three of eleven came back as the mark *plus* a smaller framed copy of itself, like
  a preview thumbnail pasted into the artwork. "Draw it simpler than the full mark" is read as
  "show both". A favicon is a downscale of the mark and should simply be one.
- **Exact accent fidelity.** Every accent renders lighter than the hex it is given, and lightening
  drags the hue — measured drift runs 1 to 22 degrees across the set, and `trade` needed seven
  attempts before its card was both dark-grounded and the right green. **Recolour rather than
  reprompt**: generate in greyscale and map the ink to the registry hex.
- **Sticking to a dark ground.** The very first image came back mid-grey taupe with construction
  guides drawn in, and one later attempt inverted to a near-white field. The ground had to be
  restated as its own final paragraph, and it still needs verifying per asset.
- **Anything requiring an exact count.** "Five valance strokes", "four segments", "a nine-cell
  grid" are approximated, always plausibly and never exactly.

The short version: **let the model draw the marks, and set the type yourself.**

## 6. Reproducing

`generate.ts` imports from the sibling `studio/` and `ui/` checkouts, so this repository is not
self-contained — the artefacts are, the runner is not. That is the same arrangement the estate's
other packages use. Clone `cloudsforge-online/micro` beside it, put a Foundry endpoint and key in
`studio/.env.local`, and run.

There is **no seed** on any entry, and the column says `null` rather than being absent. This
deployment of FLUX 2 Pro accepts no seed parameter, so nothing true could be recorded; the field
is kept so the absence is a stated fact and a seeded model later has somewhere to put one. **These
images are therefore not bit-reproducible.** The prompt, model and checksum are recorded so a
regeneration can be *compared* to what shipped, which is what provenance is for.
